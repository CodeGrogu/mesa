# Intel HD 620 Linux driver audit

Device `8086:5916`, Kaby Lake GT2, one slice, three subslices and 24 EUs. Running kernel `7.0.0-43-generic` uses i915. Installed Mesa is `26.0.8-1ubuntu0.3` and Intel iHD is `26.1.2`. The pinned unmodified and patched ANV builds are from Mesa `0e9e1086bb86`. The checked-out kernel source is `20eef29b7c8465` and was used for source review. The audit did hardware tests on the installed kernel. [Host inventory](evidence/host.txt) · [i915 queries](evidence/i915-uapi.txt) · [Pinned ANV library hashes](../HD620-benchmark/provenance.json)

### Why the timer and depth findings are different

The timer defect affects profiling accuracy. In the checked-out Iris tree, timestamp snapshots go to the render batch while compute dispatches go to the compute batch. The hardware engine can be the same while the command streams are separate. The explicit-drain control makes the measured interval scale with the dispatch. As a separate control, the same OpenGL script through Zink on the installed ANV ICD reported 10.80 ms for timestamp pairs and 10.83 ms for `GL_TIME_ELAPSED` on the 256-round workload. Cross-batch ordering is the leading source-level explanation. Establishing the cause requires a submission trace or an ordering fix with targeted tests. Correctness for generic GL requires both boundaries to cover the relevant preceding work, including graphics and compute. [Zink control](evidence/gl-compute-zink.txt) · [Iris timestamp emission](../mesa/src/gallium/drivers/iris/iris_query.c#L195) · [Iris dispatch batch](../mesa/src/gallium/drivers/iris/iris_draw.c#L397) · [GL timer requirements](https://registry.khronos.org/OpenGL/extensions/ARB/ARB_timer_query.txt) · [OpenCL event requirements](https://registry.khronos.org/OpenCL/specs/unified/refpages/man/html/clGetEventProfilingInfo.html)

The Iris defect also reproduced on Mesa 27.0.0-devel built from the checked-out revision. The GL timestamp interval for 256 rounds was 333 ns, and the median `GL_TIME_ELAPSED` value was 0 ns. Explicit drains produced an 11.09 ms interval and the output checks passed in all three modes. The test logged both build-tree libraries from its process map. The staged Rusticl test used 26.0.8. [Fresh build reproduction](evidence/gl-compute-current-iris.txt) · [Build identity](evidence/iris-build-sha256.txt) · [Build log](evidence/iris-build.txt)

The depth result measures a specific performance loss where ANV disables HiZ when the image has more than one mip on Gen9. The code names BLORP's multi-LOD depth path as unfinished. The depth test performs repeated attachment load-op clears and reads back a pixel after each submitted group. The timed interval ends before transition to transfer layout and readback. Results are eight samples per condition with alternating mip order, using the GPU clock. The depth probe completed with Vulkan Validation Layers loaded on the installed ICD. The final timings were rerun after the Iris build completed. [Gen9 guard](../mesa/src/intel/vulkan/anv_image.c#L2035) · [Depth probe](vulkan-depth.c) · [Validation log](evidence/depth-validation.txt)

## Implemented, conditional, missing and outdated

- **Implemented and exercised.** Iris OpenGL and GLES rendering, ANV Vulkan graphics and compute, i915 GEM/PRIME/BCS and timeline synchronization, and the tested VA media paths. The capability dumps list the wider advertised APIs. Enumeration alone is evidence of reporting. [Vulkan](evidence/vulkan-installed.txt) · [VA profiles](evidence/va-iHD.txt) · [OpenGL/GLES/EGL](evidence/egl.txt)
- **Conditional or incomplete.** Vulkan Video opt-in and codec gates, unavailable Gen9 multi-mip HiZ, native ANV sparse residency absent, no dedicated ANV copy family, staged OpenCL only, and standalone VA/EGL interop coverage. ANV has an opt-in cooperative-matrix emulation path from the initial source audit. No compute workload used it. FP32 atomics must be broken down by operation and memory class. Supported float16 shader features do not imply support for FP32 atomic add. [Original capability inventory](../HD620-driver-audit.md) · [ANV capabilities](evidence/vulkan-patched.txt)
- **Missing software feature with working hardware precedent.** HEVC Main and Main10 Vulkan encoding. The tested iHD encoder establishes that the hardware can do this. ANV's current encode gate requires Gen12 for HEVC. A gate change alone would provide no Gen9 implementation or conformance evidence. [ANV gate](../mesa/src/intel/vulkan/anv_physical_device.c#L380) · [iHD verification](evidence/media-smoke.txt)
- **Software updates already in the Mesa checkout.** On this host, the installed Vulkan ICD reports 183 device extensions and both pinned builds report the same 199. The 16 new exposures include descriptor heap, indirect memory copy, an internally synchronized queue feature and Maintenance 11/12. This is an enumeration delta between builds. It does not attribute the delta to the eight local fixes or verify workloads for those 16 extensions. [Set difference](evidence/vulkan-extension-delta.txt)
- **Outdated alternatives.** The installed legacy VA i965 driver initializes and advertises a different set of profiles. Intel archived its repository in January 2025 and directs users to iHD for continued updates. The i915 *kernel* driver remains the Kaby Lake path. Xe kernel support starts on newer hardware. [i965 capability snapshot](evidence/va-i965.txt) · [Intel i965 archive](https://github.com/intel/intel-vaapi-driver) · [Xe acceptance plan](https://docs.kernel.org/gpu/rfc/xe.html)
- **Outdated compute metadata.** Staged Rusticl reports a 400 MHz device clock from an Iris constant. The kernel reports a configured 300–1,000 MHz GT range, and the graphics runs sampled 1,000 MHz. Using an actual valid device frequency would make telemetry more useful. OpenCL 3.0 permits implementation-defined clock reporting on a variable-frequency device, so these values do not establish a second conformance defect. [Rusticl capability snapshot](evidence/rusticl-container.txt) · [Iris compute capability](../mesa/src/gallium/drivers/iris/iris_screen.c#L259) · [OpenCL device information](https://registry.khronos.org/OpenCL/specs/unified/refpages/man/html/clGetDeviceInfo.html)
- **Hardware and backend constraints.** Fixed-function AV1 and native ray tracing, mesh shading and systolic matrix acceleration are outside the tested Gen9 hardware or generation paths. An API feature may still be implementable with a software or shader fallback. Sparse residency would need demonstrated residency and aliasing semantics on this backend. No capability bit was changed during the audit. [Original architecture review](../HD620-driver-audit.md) · [ANV feature and backend gates](../mesa/src/intel/vulkan/anv_physical_device.c)

## Graphics measurements

Four two-second trials per scene on a live desktop; Vulkan driver order alternated. Each Vulkan log pins the selected ICD and records 800×600 headless results. These are light, short scenes and peak values are not game benchmarks. The paired patched-versus-base changes varied in both directions, including one large negative outlier for host-visible vertex data. There is no consistent graphics speedup in this sample. Per-process i915 snapshots and sampled GPU clocks are stored beside the logs. [Raw results](evidence/graphics/timings.csv) · [Runner](graphics-bench.py) · [DRM usage-counter semantics](https://docs.kernel.org/gpu/drm-usage-stats.html)

| --- | ---: | ---: | ---: |
| Vertex, device-local | 8,093 | 7,593.5 | 7,569 |
| Vertex, host-visible | 7,909.5 | 7,629 | 7,412.5 |
| Phong shading | 5,461 | 5,031 | 5,020 |

OpenGL's glmark2 geometry scene was faster using vertex buffer objects in all four measured pairs. Median scores were 7,677.5 fps with a VBO and 4,462.5 fps without. This is an application rendering-path effect, with no attribution to a specific Iris code change. Earlier FFmpeg tests similarly measured the pipeline benefit of keeping decoded frames GPU-resident. ## Verification workflow and limits

The preserved probes are [hardware inventory](inventory.sh), [i915 queries](i915-inventory.c), [i915 smoke](i915-smoke.c), [GL compute timing](gl-compute-timing.py), [staged Rusticl](run-rusticl.sh), [OpenCL workload](opencl-smoke.py), [Vulkan compute](run-vulkan-compute.sh), [depth timing](run-depth.sh), [VA smoke](media-smoke.sh), [VA/Vulkan pipeline](media-interop.sh) and [DMA-BUF EGL import](va-egl-import.py). Distribution tool packages were downloaded and unpacked under `tools/` without registering host packages or drivers. Compile probes used the existing Mesa build container. Timed comparisons should be rerun with the host otherwise idle.

The independent reviewer approved the audit within its stated coverage. They checked the subsystem claims against the raw evidence and reran the OpenGL compute timer on installed and freshly built Iris. In the fresh-build 256-round test, the timestamp interval was 250 ns, `GL_TIME_ELAPSED` was 0 ns, and completion took 11.48 ms. The explicit-drain control reported 11.55 ms. The build hashes matched and the sampled output checks passed. [Fresh Iris rerun](evidence/independent-review/iris-current.log) · [Installed Iris rerun](evidence/independent-review/iris-installed.log) · [Build hashes](evidence/independent-review/iris-sha256)

The reviewer also reran all six ANV depth configurations, eight samples each. Patched ANV took 2.44 ms for one allocated mip and 27.66 ms for four, or 11.34× for this run. With HiZ disabled, the same cases took 29.04 and 27.27 ms. In each group the probe checks the final clear value at the center of mip 0. The original audit's 9.34× ratio and this rerun describe separate measurements of the same microbenchmark. [Patched rerun](evidence/independent-review/depth-patched-default.log) · [HiZ-disabled control](evidence/independent-review/depth-patched-nohiz.log)

The FPS scenes, video samples and startup checks establish specific observed behaviors. Conformance, all-feature execution, battery conclusions and exhaustive correctness are still outside the verified scope. The running system's debugfs/perf access and disconnected HDMI are concrete coverage limits. No system software, kernel configuration, Mesa source or upstream repository was changed in this pass.
