## Summary

Upstream Mesa MR 45047 ("brw: Fix SIMD32 three-source hangs and incorrect FP16 results") fixes both of its target bugs on Kaby Lake. The MR author tested Comet Lake and Whiskey Lake only. This issue records the Kaby Lake results so they can be passed upstream.

Hardware: Intel HD 620 (KBL GT2, `8086:5916`), i915, Linux 7.0. Base: Mesa main `0e9e1086bb86`.

## mesa#16528: wrong FP16 results at SIMD32

`fp16-simd32/lanemask.comp` runs FP16 `fma` under divergent control flow at required subgroup sizes 8, 16 and 32 and checks 65,536 lanes exactly.

| Driver | SIMD8/16 | SIMD32 |
| --- | --- | --- |
| Mesa 26.0.8 | 0 errors | 31,931 wrong values, all in lanes 16–31 |
| main | 0 | 38,349 wrong values |
| main + MR 45047 | 0 | **0** (3 repeats) |

A single active lane (lane 21) left lane 21 unwritten and wrote lane 29, which is the L − 8 behaviour. The MR's code splits `mad (32) … :hf {Align16}` into `mad (16)` + `mad (16|M16)`. The brw unit tests (410) and gen unit tests (150) pass.

## mesa#16526: hang from a SIMD32 `mad` with a conditional modifier

`hang-proofs/cmod-v1.comp` (an FP16 multiply-add followed by a leaky ReLU) compiles on main to `mad (32) (lt)f0.0 … :hf {Align16}`, the encoding the Skylake PRM forbids.

| Driver | Result |
| --- | --- |
| main | `VK_ERROR_DEVICE_LOST` on the first submission; i915 logs `GPU HANG: ecode 9:1:8ed8fff3` |
| main + MR 45047 | 150/150 submissions completed (3 shader variants) |

Logs and assembly are under [`fp16-simd32`](https://github.com/CodeGrogu/mesa/tree/hd620-audit/HD620-full-audit/fp16-simd32) and [`hang-proofs`](https://github.com/CodeGrogu/mesa/tree/hd620-audit/HD620-full-audit/hang-proofs).
