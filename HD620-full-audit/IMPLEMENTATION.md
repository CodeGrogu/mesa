## Questions recorded for the first implementation pass

1. What orders work across flushes and timestamp boundaries? A timestamp command and a compute dispatch can land in separate Iris batches with no shared resource to create a dependency.
2. What data can an HEVC decoder safely read? Mapping a source buffer during command recording would miss valid writes ordered at execution. A host-only assumption also excludes device-side input. The existing HuC path prepares HCP slice commands during execution.
3. Is multi-mip HiZ genuinely active, and do clears, draws and transitions preserve pixels across mips and layers? The audit's center-pixel mip-0 timing test is only one test.
4. Which new routes improve a real workload? Measure isolated and concurrent work before broadening exposure. An engine no-op and short encode samples establish reachability and basic output.
5. Which behavior is an API feature gap, driver bug, runtime dependency, or hardware limit? Confirm the distinction for each remaining row before closing it.

Sol traced Iris's render-batch timestamps, compute-batch dispatch and the shared-buffer hazard limitation. Existing GPU syncobjs are relevant to both boundary directions, including already-flushed work. Sol also traced the old HEVC host slice parser and the checkout's HuC-generated batch. A host parser alone does not satisfy Vulkan's execution ordering. The x265 fixtures exercise inter frames, multiple GOPs and two image formats. A Vulkan API-level late-write test and a verified multi-slice corpus are separate prerequisites. [HEVC fixture generator](hevc-regression-inputs.sh) · [Current HEVC decode path](../mesa/src/intel/vulkan/genX_cmd_video.c#L292) · [Earlier slice parser](evidence/hardware-paths/mesa-26.0.8-video.c#L669)

The Vulkan registry restricts `vkCmdDecodeVideoKHR` to primary command buffers. Test reuse of those primary buffers and the driver-internal second-level batches independently. A late-write case can record decode first and then submit an upload on a transfer-capable queue, with appropriate queue-family ownership and a semaphore covering the video decode read. The video-only queue need not support buffer copy commands.
